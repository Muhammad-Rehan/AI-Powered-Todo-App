Spec Alignment Skill

## Metadata
name: spec-alignment
description: Use for ensuring implementation aligns with specifications and requirements

## Overview
This Skill provides specialized knowledge for ensuring implementation aligns with specifications and requirements. When developing features, implementing functionality, or verifying that code matches requirements, apply these guidelines to ensure proper specification compliance and requirement fulfillment.

## Requirement Traceability

- Map implementation elements to specific requirements
- Maintain traceability matrix between specs and code
- Track feature implementation against user stories
- Verify that all requirements are addressed
- Identify any gaps between specs and implementation
- Document deviation from original specifications

## Specification Analysis

- Thoroughly analyze feature specifications
- Identify functional and non-functional requirements
- Understand acceptance criteria and test conditions
- Clarify ambiguous requirements early
- Identify dependencies between requirements
- Recognize implicit requirements from context

## Implementation Verification

- Verify code implements specified behavior
- Test against acceptance criteria
- Validate functional requirements are met
- Check non-functional requirements are satisfied
- Ensure performance targets are achieved
- Verify security requirements are implemented

## Design Consistency

- Ensure architectural decisions align with specs
- Maintain consistency with design patterns from specs
- Verify component interactions match specifications
- Check interface contracts are fulfilled
- Validate data flow matches spec requirements
- Confirm system behavior matches specification

## Quality Assurance

- Create tests based on specification requirements
- Verify edge cases from specifications
- Test error handling as specified
- Validate user experience matches spec
- Check accessibility requirements are met
- Ensure compliance with specified standards

## Change Management

- Assess impact of specification changes
- Update implementation when specs change
- Document specification modifications
- Communicate changes to stakeholders
- Re-validate implementation after spec changes
- Track version alignment between specs and code

## Communication Protocols

- Report specification ambiguities promptly
- Seek clarification on unclear requirements
- Propose solutions for specification gaps
- Document implementation decisions against specs
- Communicate potential specification conflicts
- Collaborate on specification refinements

## Testing Alignment

- Create test cases from specification requirements
- Verify tests cover all specified scenarios
- Validate error conditions from specs
- Test boundary conditions from specifications
- Ensure performance tests match spec requirements
- Check security tests align with security specs

## Documentation Alignment

- Ensure documentation matches implemented features
- Update docs when implementation changes
- Verify API documentation matches actual endpoints
- Keep user guides aligned with actual functionality
- Update troubleshooting guides with implementation details
- Maintain consistency between specs and docs

## Stakeholder Validation

- Demonstrate features against specifications
- Validate implementation with business stakeholders
- Confirm user experience matches requirements
- Get sign-off on specification compliance
- Address stakeholder concerns about alignment
- Facilitate specification review meetings

## Continuous Verification

- Implement specification compliance checks
- Use automated tools to verify alignment
- Conduct regular specification reviews
- Monitor for specification drift during development
- Perform periodic alignment audits
- Establish specification compliance metrics

## Risk Management

- Identify risks of specification non-compliance
- Assess impact of specification gaps
- Plan mitigation strategies for compliance issues
- Flag specification conflicts early
- Document compliance risks and resolutions
- Monitor specification compliance throughout development

## When to Apply

Apply these guidelines whenever implementing:
- Feature development against specifications
- Requirement analysis and design
- Code review and quality assurance
- Testing and validation activities
- Change management processes
- Stakeholder communication and sign-off

## Development Standards

- Always verify implementation against original specifications
- Document any deviations from specifications
- Seek clarification for ambiguous requirements
- Maintain traceability between specs and implementation
- Regularly validate ongoing work against specifications
