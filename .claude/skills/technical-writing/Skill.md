Technical Writing Skill

## Metadata
name: technical-writing

## Overview
This Skill provides specialized knowledge for creating clear, accurate, and effective technical documentation. When writing technical specifications, API documentation, user guides, or system documentation, apply these guidelines to ensure comprehensive, accessible, and maintainable technical content.

## Documentation Structure

- Organize content with clear headings and sections
- Use consistent formatting and styling
- Implement logical information hierarchy
- Create comprehensive table of contents
- Include cross-references between related topics
- Structure content for different user personas

## Clarity and Precision

- Use clear, concise language
- Define technical terms and acronyms
- Avoid ambiguous or subjective language
- Use active voice when possible
- Write for the intended audience level
- Include specific examples and use cases

## Technical Accuracy

- Verify all technical information and code samples
- Test code examples and configurations
- Include version information for dependencies
- Document limitations and constraints
- Provide accurate parameter and return value information
- Validate all links and references

## API Documentation

- Document all endpoints with request/response examples
- Include parameter validation rules and constraints
- Provide clear error response documentation
- Include authentication and authorization requirements
- Document rate limits and usage restrictions
- Include example API calls and responses

## Setup and Installation

- Provide clear prerequisite information
- Include step-by-step installation procedures
- Document environment variable requirements
- Include troubleshooting sections
- Provide common configuration examples
- Include system requirements and compatibility

## Code Documentation

- Write meaningful function/method comments
- Document parameters, return values, and exceptions
- Include usage examples in code comments
- Follow consistent commenting standards
- Document complex algorithms and business logic
- Explain design decisions and trade-offs

## Visual Elements

- Include diagrams to illustrate architecture
- Use screenshots to clarify UI interactions
- Create flowcharts for complex processes
- Use tables for parameter references
- Include code syntax highlighting
- Maintain consistent visual style

## Maintenance and Updates

- Include version history and changelog
- Document deprecation notices clearly
- Plan for documentation maintenance
- Include contribution guidelines
- Use version control for documentation
- Schedule regular documentation reviews

## Accessibility

- Use semantic markup for accessibility
- Include alt text for images
- Provide text alternatives for diagrams
- Follow accessibility guidelines
- Use readable fonts and colors
- Ensure keyboard navigability

## Audience Consideration

- Write for different skill levels
- Include beginner-friendly explanations
- Provide advanced usage examples
- Consider different user goals and needs
- Address common questions proactively
- Anticipate user confusion points

## Quality Assurance

- Proofread for grammar and spelling errors
- Verify factual accuracy of content
- Test all procedures and examples
- Review for completeness and consistency
- Validate all external links and references
- Seek feedback from technical reviewers

## Style Guidelines

- Use consistent terminology throughout
- Follow established style guides when applicable
- Maintain consistent formatting patterns
- Use appropriate technical language level
- Include proper attribution for sources
- Follow company or project style standards

## Searchability

- Include relevant keywords for search
- Use descriptive headings and titles
- Include metadata for documentation systems
- Structure content for search engine optimization
- Provide clear navigation paths
- Include related topic suggestions

## Version Control

- Track documentation changes with code
- Use version control for documentation
- Maintain documentation release cycles
- Include release notes for documentation changes
- Coordinate documentation with code releases
- Archive old documentation versions appropriately

## When to Apply

Apply these guidelines whenever creating:
- API documentation and reference materials
- User guides and tutorials
- System architecture documentation
- Technical specifications and requirements
- Code comments and inline documentation
- Configuration guides and best practices

## Writing Standards

- Always verify technical accuracy before publishing
- Use consistent formatting and style throughout
- Include practical examples and use cases
- Write for the intended audience level
- Maintain documentation currency with code changes
